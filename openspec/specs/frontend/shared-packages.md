# Shared Monorepo Packages Specification

> Baseline specification for the Foundation Template.
> This document is the source of truth. All implementations must conform to these specs.

## Overview

The monorepo contains six shared packages under `packages/` that are consumed by both `apps/web` (Next.js) and `apps/mobile` (Expo). These packages enforce the DRY principle across platforms: API types are generated once, validation schemas are written once, UI primitives are implemented once, and business logic hooks exist in a single location. All packages use the `@repo/` scope and follow strict dependency rules to prevent circular imports and deep dependency chains.

## Specifications

### 1. packages/api-client/

**Purpose:** Auto-generated TypeScript types from the Django OpenAPI spec + a type-safe HTTP client wrapper + React Query hooks.

#### Directory Structure

```
packages/api-client/
  src/
    types.d.ts               # Generated by openapi-typescript (DO NOT EDIT)
    client.ts                 # openapi-fetch client factory
    auth-providers.ts         # WebAuthProvider, MobileAuthProvider
    hooks.ts                  # React Query hooks wrapping the client
    index.ts                  # Re-exports
  openapi.json                # Cached OpenAPI spec from Django (committed to git)
  package.json
  tsconfig.json
```

#### Type Generation Pipeline

The type generation pipeline is the bridge between the Python backend and TypeScript frontends.

```
Step 1: Django Ninja Extra generates OpenAPI 3.0 spec at runtime
  |
  v
Step 2: Export spec to file
  $ python manage.py export_openapi_schema > packages/api-client/openapi.json
  |
  v
Step 3: Generate TypeScript types
  $ pnpm --filter @repo/api-client generate:types
  $ openapi-typescript openapi.json -o src/types.d.ts
  |
  v
Step 4: openapi-fetch uses types.d.ts for type-safe API calls
  No code generation needed for the client -- types power inference
```

| Step | Tool | Input | Output |
|------|------|-------|--------|
| Export OpenAPI spec | Django management command | Running Django server or `manage.py` | `openapi.json` |
| Generate TypeScript types | `openapi-typescript` | `openapi.json` | `src/types.d.ts` |
| Type-safe client | `openapi-fetch` | `src/types.d.ts` (compile-time) | Runtime fetch calls with full type inference |

The `openapi.json` and `src/types.d.ts` files are committed to git so frontend developers can work without running the Django backend.

#### Client Wrapper

```ts
// src/client.ts
import createClient from "openapi-fetch";
import type { paths } from "./types";

export type AuthProvider = {
  onRequest: (request: Request) => Promise<Request> | Request;
  onResponse: (response: Response, request: Request) => Promise<Response> | Response;
};

export function createApiClient(baseUrl: string, authProvider?: AuthProvider) {
  const client = createClient<paths>({ baseUrl });

  if (authProvider) {
    client.use({
      async onRequest({ request }) {
        return authProvider.onRequest(request);
      },
      async onResponse({ response, request }) {
        return authProvider.onResponse(response, request);
      },
    });
  }

  return client;
}
```

#### Auth Providers

Two auth providers handle the platform split: cookies for web, JWT for mobile.

```ts
// src/auth-providers.ts
import type { AuthProvider } from "./client";

/**
 * Web auth: relies on httpOnly session cookies.
 * No Authorization header needed. Cookies are sent automatically
 * because requests go through Next.js rewrites (same-origin).
 */
export const WebAuthProvider: AuthProvider = {
  onRequest(request) {
    // Cookies are sent automatically by the browser for same-origin requests
    return request;
  },
  onResponse(response) {
    return response;
  },
};

/**
 * Mobile auth: attaches JWT Bearer token from secure storage.
 * Handles 401 by attempting token refresh.
 */
export function createMobileAuthProvider(options: {
  getAccessToken: () => Promise<string | null>;
  getRefreshToken: () => Promise<string | null>;
  storeTokens: (access: string, refresh: string) => Promise<void>;
  clearTokens: () => Promise<void>;
  refreshUrl: string;
  onAuthFailure: () => void;
}): AuthProvider {
  let isRefreshing = false;
  let refreshPromise: Promise<string | null> | null = null;

  async function refreshAccessToken(): Promise<string | null> {
    const refreshToken = await options.getRefreshToken();
    if (!refreshToken) return null;

    const response = await fetch(options.refreshUrl, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ refresh: refreshToken }),
    });

    if (!response.ok) {
      await options.clearTokens();
      options.onAuthFailure();
      return null;
    }

    const data = await response.json();
    await options.storeTokens(data.access, data.refresh || refreshToken);
    return data.access;
  }

  return {
    async onRequest(request) {
      const token = await options.getAccessToken();
      if (token) {
        request.headers.set("Authorization", `Bearer ${token}`);
      }
      return request;
    },
    async onResponse(response, request) {
      if (response.status === 401) {
        if (!isRefreshing) {
          isRefreshing = true;
          refreshPromise = refreshAccessToken();
        }
        const newToken = await refreshPromise;
        isRefreshing = false;
        refreshPromise = null;

        if (newToken) {
          request.headers.set("Authorization", `Bearer ${newToken}`);
          return fetch(request);
        }
      }
      return response;
    },
  };
}
```

#### React Query Hooks

Thin wrappers around `openapi-fetch` calls that return React Query query/mutation objects.

```ts
// src/hooks.ts
import { useQuery, useMutation, type UseQueryOptions } from "@tanstack/react-query";
import type { paths } from "./types";
import { createApiClient } from "./client";

// These hooks receive the client as a parameter (dependency injection).
// The app configures the client with the correct auth provider at startup.

export function useCurrentUser(client: ReturnType<typeof createApiClient>) {
  return useQuery({
    queryKey: ["currentUser"],
    queryFn: async () => {
      const { data, error } = await client.GET("/api/v1/users/me");
      if (error) throw error;
      return data;
    },
  });
}

export function useUpdateUser(client: ReturnType<typeof createApiClient>) {
  return useMutation({
    mutationFn: async (body: paths["/api/v1/users/me"]["patch"]["requestBody"]["content"]["application/json"]) => {
      const { data, error } = await client.PATCH("/api/v1/users/me", { body });
      if (error) throw error;
      return data;
    },
  });
}
```

#### Auth Schemas

```ts
// src/auth.ts
import { z } from "zod";
import { emailSchema, passwordSchema } from "./common";

export const loginSchema = z.object({
  email: emailSchema,
  password: z.string().min(1, "Password is required"),
});

export const signupSchema = z.object({
  email: emailSchema,
  password: passwordSchema,
  password_confirm: z.string().min(1, "Please confirm your password"),
  first_name: z.string().min(1, "First name is required").max(50),
  last_name: z.string().min(1, "Last name is required").max(50),
}).refine((data) => data.password === data.password_confirm, {
  message: "Passwords do not match",
  path: ["password_confirm"],
});

export const resetPasswordSchema = z.object({
  email: emailSchema,
});

export const resetPasswordConfirmSchema = z.object({
  password: passwordSchema,
  password_confirm: z.string().min(1, "Please confirm your password"),
}).refine((data) => data.password === data.password_confirm, {
  message: "Passwords do not match",
  path: ["password_confirm"],
});

// Type exports via z.infer<>
export type LoginInput = z.infer<typeof loginSchema>;
export type SignupInput = z.infer<typeof signupSchema>;
export type ResetPasswordInput = z.infer<typeof resetPasswordSchema>;
export type ResetPasswordConfirmInput = z.infer<typeof resetPasswordConfirmSchema>;
```

### 3. packages/ui/

**Purpose:** Cross-platform UI primitives built with React Native core components. These render natively on mobile (via Metro/React Native) and as DOM elements on web (via react-native-web).

#### Directory Structure

```
packages/ui/
  src/
    button.tsx                # Cross-platform Button
    button.web.tsx            # Web-specific Button variant (optional)
    button.native.tsx         # Native-specific Button variant (optional)
    text.tsx                  # Cross-platform Text
    input.tsx                 # Cross-platform TextInput
    card.tsx                  # Cross-platform Card container
    loading.tsx               # ActivityIndicator wrapper
    index.ts                  # Re-exports
  package.json
  tsconfig.json
```

#### What is Shared vs Platform-Specific

| Shared in `@repo/ui` | NOT Shared (platform-specific) |
|-----------------------|-------------------------------|
| `Button` (Pressable + Text) | Navigation components (sidebar, tab bar, stack header) |
| `Text` (styled Text primitive) | Complex forms (Shadcn/ui on web, native inputs on mobile) |
| `Input` (TextInput primitive) | Animations (CSS transitions on web, Reanimated on mobile) |
| `Card` (View with styling) | Responsive layouts (CSS Grid on web, Flexbox on mobile) |
| `Loading` (ActivityIndicator) | Modals / dialogs (Shadcn/ui Dialog vs RN Modal) |
|  | Data tables (web only) |
|  | Gesture handlers (mobile only) |
|  | Platform-specific icons |

#### Strict Boundary Rules

- No `expo-*` imports
- No `react-native-reanimated` imports
- No `react-native-gesture-handler` imports
- No navigation imports (`expo-router`, `@react-navigation/*`)
- No `Platform.OS` checks beyond 2 per component (if more needed, split into `.web.tsx` / `.native.tsx`)
- Only `react-native` core APIs: `View`, `Text`, `Pressable`, `TextInput`, `Image`, `ScrollView`, `FlatList`, `ActivityIndicator`, `StyleSheet`

#### Platform Split Pattern

When a component needs different implementations per platform, use file extensions:

```
// Default (fallback for any platform)
button.tsx

// Web-specific (resolved by webpack in Next.js)
button.web.tsx

// Native-specific (resolved by Metro in Expo)
button.native.tsx
```

Metro resolves `.native.tsx` before `.tsx`. Webpack resolves `.web.tsx` before `.tsx`. This is automatic -- no bundler configuration needed beyond what is already in `next.config.ts` and `metro.config.js`.

#### useAuth Hook

```ts
// src/hooks/use-auth.ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { useAuthContext } from "../providers/auth-provider";
import type { LoginInput, SignupInput } from "@repo/validation";

export function useAuth() {
  const context = useAuthContext();
  const queryClient = useQueryClient();

  const loginMutation = useMutation({
    mutationFn: async (input: LoginInput) => {
      return context.login(input.email, input.password);
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["currentUser"] });
    },
  });

  const logoutMutation = useMutation({
    mutationFn: async () => {
      return context.logout();
    },
    onSuccess: () => {
      queryClient.clear();
    },
  });

  const registerMutation = useMutation({
    mutationFn: async (input: SignupInput) => {
      return context.register(input);
    },
  });

  return {
    isAuthenticated: context.isAuthenticated,
    isLoading: context.isLoading,
    user: context.user,
    login: loginMutation.mutateAsync,
    logout: logoutMutation.mutateAsync,
    register: registerMutation.mutateAsync,
    loginError: loginMutation.error,
    isLoggingIn: loginMutation.isPending,
  };
}
```

#### useUser Hook

```ts
// src/hooks/use-user.ts
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import type { UpdateProfileInput } from "@repo/validation";

export function useUser(client: any) {
  const queryClient = useQueryClient();

  const userQuery = useQuery({
    queryKey: ["currentUser"],
    queryFn: async () => {
      const { data, error } = await client.GET("/api/v1/users/me");
      if (error) throw error;
      return data;
    },
  });

  const updateMutation = useMutation({
    mutationFn: async (input: UpdateProfileInput) => {
      const { data, error } = await client.PATCH("/api/v1/users/me", { body: input });
      if (error) throw error;
      return data;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["currentUser"] });
    },
  });

  return {
    user: userQuery.data,
    isLoading: userQuery.isLoading,
    error: userQuery.error,
    updateProfile: updateMutation.mutateAsync,
    isUpdating: updateMutation.isPending,
  };
}
```

#### Utility Functions

```ts
// src/utils/format-date.ts
export function formatDate(date: string | Date, options?: Intl.DateTimeFormatOptions): string {
  const d = typeof date === "string" ? new Date(date) : date;
  return d.toLocaleDateString("en-US", {
    year: "numeric",
    month: "short",
    day: "numeric",
    ...options,
  });
}

export function formatRelativeTime(date: string | Date): string {
  const d = typeof date === "string" ? new Date(date) : date;
  const now = new Date();
  const diffMs = now.getTime() - d.getTime();
  const diffMins = Math.floor(diffMs / 60000);
  const diffHours = Math.floor(diffMins / 60);
  const diffDays = Math.floor(diffHours / 24);

  if (diffMins < 1) return "just now";
  if (diffMins < 60) return `${diffMins}m ago`;
  if (diffHours < 24) return `${diffHours}h ago`;
  if (diffDays < 30) return `${diffDays}d ago`;
  return formatDate(d);
}
```

### Package Naming Convention

All internal packages use the `@repo/` scope to avoid naming collisions with npm packages and follow Turborepo conventions.

| Package | Scope Name | Path |
|---------|-----------|------|
| API Client | `@repo/api-client` | `packages/api-client/` |
| Validation | `@repo/validation` | `packages/validation/` |
| UI Primitives | `@repo/ui` | `packages/ui/` |
| Business Logic | `@repo/business-logic` | `packages/business-logic/` |
| ESLint Config | `@repo/config-eslint` | `packages/config-eslint/` |
| TypeScript Config | `@repo/config-ts` | `packages/config-ts/` |

### Dependency Rules

Packages follow a flat dependency graph. No dependency chain is longer than one hop.

```
                  ┌──────────────┐
                  │  config-ts   │   (no monorepo deps)
                  │  config-eslint│
                  └──────────────┘
                        ^
       ┌────────────────┼────────────────┐
       |                |                |
 ┌───────────┐   ┌───────────┐   ┌───────────┐
 │ validation│   │    ui     │   │api-client │
 │  (zod)    │   │  (RNW)   │   │(generated)│
 └─────┬─────┘   └───────────┘   └─────┬─────┘
       |                                |
       |         ┌───────────┐          |
       └────────>│ business- │<─────────┘
                 │  logic    │
                 └─────┬─────┘
                       |
            ┌──────────┼──────────┐
            v          v          v
       ┌────────┐ ┌────────┐ ┌────────┐
       │  web   │ │ mobile │ │ future │
       └────────┘ └────────┘ └────────┘
```

| Package | Depends On (monorepo) | Depends On (external) |
|---------|----------------------|----------------------|
| `config-ts` | None | None |
| `config-eslint` | None | `typescript-eslint`, `eslint-plugin-react`, `@next/eslint-plugin-next` |
| `validation` | None | `zod` |
| `ui` | None | `react-native` (peer) |
| `api-client` | None | `openapi-fetch`, `openapi-typescript`, `@tanstack/react-query` (peer) |
| `business-logic` | `api-client`, `validation` | `@tanstack/react-query` (peer), `react` (peer) |
| `web` (app) | All packages it needs | Next.js, Shadcn/ui, Tailwind, etc. |
| `mobile` (app) | All packages it needs | Expo, React Native, etc. |

**Hard rule:** No package depends on another package that itself depends on a third monorepo package. The maximum chain depth is: `app -> business-logic -> api-client` (two hops from app, one hop between packages).

### GIVEN/WHEN/THEN Scenarios

#### Scenario: Type Generation After API Change

```
GIVEN a developer has modified a Django Ninja Pydantic schema

  AND openapi-typescript regenerates src/types.d.ts from the new spec
  AND TypeScript compilation in apps/web and apps/mobile catches any type mismatches
  AND the developer fixes type errors before committing
```

```
  AND the committed openapi.json does not match the current Django output

  AND the CI job fails with a message: "OpenAPI spec is stale. Run 'pnpm turbo generate:api-types' and commit the result."
```

## Constraints

- **All packages are `"private": true`.** None are published to npm. They are consumed via pnpm workspace protocol (`workspace:*`).
- **No circular dependencies.** The dependency graph is a DAG. `api-client` does not depend on `business-logic`. `ui` does not depend on `validation`.
- **No deep chains.** Maximum one hop between shared packages. Apps can depend on any package directly.
- **`@repo/ui` has zero monorepo dependencies.** It must render with only `react` and `react-native` as peers. No Zod, no API client, no business logic.
- **Generated files are committed.** `openapi.json` and `types.d.ts` in `@repo/api-client` are committed to git so frontend development is decoupled from a running Django server.
- **`src/index.ts` as main entry.** All packages use source entry points (not built `dist/`) for development. Metro and webpack/turbopack both handle TypeScript compilation.
- **Packages do not import from apps.** The dependency direction is always `app -> package`, never `package -> app`.
- **Pin codegen tool versions.** `openapi-typescript` and `openapi-fetch` versions are pinned (not `latest`, not `^latest`) to prevent generated output format changes.
