<task type="auto">
  <name>Task 2: Add schemathesis CI job to .github/workflows/ci.yml</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Append the following `schemathesis` job to `.github/workflows/ci.yml` AFTER the `mobile` job block.

    ```yaml
      schemathesis:
        name: API Contract Fuzzing (schemathesis)
        runs-on: ubuntu-latest

        services:
          postgres:
            image: postgres:16
            env:
              POSTGRES_PASSWORD: postgres
              POSTGRES_DB: foundation_schemathesis
            options: >-
              --health-cmd pg_isready
              --health-interval 10s
              --health-timeout 5s
              --health-retries 5
            ports:
              - 5432:5432

        steps:
          - name: Checkout code
            uses: actions/checkout@v4

          - name: Set up Python
            uses: actions/setup-python@v5
            with:
              python-version: "3.12"
              cache: "pip"
              cache-dependency-path: "apps/api/pyproject.toml"

          - name: Install uv
            run: pip install uv

          - name: Install dependencies
            run: cd apps/api && uv sync

          - name: Run migrations
            run: cd apps/api && uv run python manage.py migrate
            env:
              DATABASE_URL: postgresql://postgres:postgres@localhost:5432/foundation_schemathesis  # pragma: allowlist secret
              SECRET_KEY: test-secret-key-for-ci
              DEBUG: "True"

          - name: Start Django dev server in background
            run: |
              cd apps/api && uv run python manage.py runserver 8000 &
              echo "Django server PID: $!"
            env:
              DATABASE_URL: postgresql://postgres:postgres@localhost:5432/foundation_schemathesis  # pragma: allowlist secret
              SECRET_KEY: test-secret-key-for-ci
              DEBUG: "True"
              DJANGO_SETTINGS_MODULE: config.settings.development

          - name: Wait for Django server to be ready
            run: |
              echo "Waiting for Django server..."
              for i in $(seq 1 30); do
                if wget -q -O /dev/null http://127.0.0.1:8000/api/openapi.json 2>/dev/null; then
                  echo "Django server is ready (attempt $i)"
                  break
                fi
                echo "Attempt $i/30 — server not ready yet, retrying in 2s"
                sleep 2
              done
              wget -q -O /dev/null http://127.0.0.1:8000/api/openapi.json || (echo "Django server failed to start" && exit 1)

          - name: Run schemathesis contract fuzzing
            run: |
              cd apps/api && uv run schemathesis run \
                http://127.0.0.1:8000/api/openapi.json \
                --checks all \
                --exclude-path /api/billing/webhook/ \
                --exclude-path "/api/health/" \
                --exclude-path "/api/v1/auth/" \
                --max-response-time 5000 \
                --hypothesis-max-examples 30
            env:
              DATABASE_URL: postgresql://postgres:postgres@localhost:5432/foundation_schemathesis  # pragma: allowlist secret
              SECRET_KEY: test-secret-key-for-ci
              DEBUG: "True"
    ```

    Placement decisions (Claude's discretion per CONTEXT.md):

    1. **Separate postgres service** — uses a different DB name (`foundation_schemathesis`) to avoid
       state pollution with the `api` job's test database. Schemathesis creates/modifies real DB rows;
       test isolation requires a clean database.

    2. **`--checks all`** — enables all built-in schemathesis checks: `not_a_server_error` (5xx),
       `status_code_conformance`, `content_type_conformance`, `response_schema_conformance`.
       This satisfies the success criterion "fails if any property-based request causes a 5xx
       response or a response that violates the OpenAPI schema."

    3. **`--hypothesis-max-examples 30`** — balances CI cost with coverage. Schemathesis default
       is 100 examples per endpoint; 30 is sufficient for template-level contract checking without
       excessive CI minutes.

    4. **`--max-response-time 5000`** — fails if any endpoint takes >5 seconds to respond.
       Catches accidental blocking calls or slow ORM queries introduced by new endpoints.

    5. **Excluded paths:**
       - `/api/billing/webhook/` — requires valid Stripe signature; fuzzing produces 400s by design
       - `/api/health/` — health probes return 503 when Celery/Redis absent in CI; not business logic
       - `/api/v1/auth/` — allauth endpoints use session-based CSRF flows; fuzzing creates user noise
         and false positives. Auth contract is covered by the `api` job's pytest suite.

    6. **`--exclude-path "/api/health/"` uses a prefix** — matches `/api/health/live`,
       `/api/health/ready`, and `/api/health/startup` with a single flag.

    After adding the job, verify the YAML syntax is valid:
