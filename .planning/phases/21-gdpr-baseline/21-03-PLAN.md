Anti-hydration-error pattern (established in research):

```typescript
// CORRECT: initial state false, useEffect reads localStorage
const [visible, setVisible] = useState(false);
useEffect(() => {
  const consent = localStorage.getItem("analytics_consent");
  if (!consent)
    setVisible(true); // absent → show banner
  else if (consent === "granted") initPostHog();
  else posthog.opt_out_capturing(); // "denied"
}, []);
```

posthog-js init guard (from research pitfall 4):
Use a module-level ref or check posthog.\_isIdentified() / posthog.has_opted_in_capturing() to
prevent double-init. Simplest approach: use a React useRef<boolean> initialized to false and
set to true after calling posthog.init(). Only call init if ref.current === false.

posthog.init() config (from providers.tsx existing config — carry same values):

```typescript
posthog.init(process.env.NEXT_PUBLIC_POSTHOG_KEY ?? "", {
  api_host: process.env.NEXT_PUBLIC_POSTHOG_HOST ?? "https://eu.i.posthog.com",
  capture_pageview: false,
  capture_pageleave: true,
  session_recording: { maskAllInputs: true },
  loaded: (ph) => {
    if (!process.env.NEXT_PUBLIC_POSTHOG_KEY) ph.opt_out_capturing();
  },
});
```
