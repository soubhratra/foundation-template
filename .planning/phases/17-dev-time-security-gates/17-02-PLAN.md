  <name>Task 1: Add detect-secrets and bandit hooks to .pre-commit-config.yaml</name>
  <files>.pre-commit-config.yaml</files>
  <action>
    Append two new repo blocks to `.pre-commit-config.yaml` after the existing `pre-commit/pre-commit-hooks` block.

    Block 1 — detect-secrets (DEV-01):
    ```yaml
    # Secret detection — blocks secrets at commit time (DEV-01)
    - repo: https://github.com/Yelp/detect-secrets
      rev: v1.5.0
      hooks:
        - id: detect-secrets
          args: ["--baseline", ".secrets.baseline"]
    ```

    Block 2 — bandit (DEV-02):
    ```yaml
    # Python security linting — HIGH severity only, excludes tests/ (DEV-02)
    - repo: https://github.com/PyCQA/bandit
      rev: 1.9.4
      hooks:
        - id: bandit
          args: ["-lll", "-x", "tests/"]
          files: ^apps/
    ```

    Key points:
    - detect-secrets hook requires `.secrets.baseline` to exist (Plan 17-03 generates it). Until then, developers who run pre-commit will see an error on the detect-secrets hook — this is expected and acceptable.
    - bandit `files: ^apps/` scopes to the apps/ directory only, excluding test files (the `-x tests/` arg is belt-and-suspenders for the pre-commit hook's file staging).
    - `-lll` = HIGH severity only (three lowercase L's per bandit docs).
    - Do NOT add `rev:` with a `v` prefix for bandit — the bandit PyPI version `1.9.4` does not use a `v` tag in its pre-commit hooks.

  </action>

  <files>.github/workflows/ci.yml, .pip-audit-ignore</files>
  <action>
    **Part A — .github/workflows/ci.yml:**

    In the `api` job, insert two new steps AFTER the "Install dependencies" step (`uv sync`) and BEFORE the "Run ruff lint" step:

    Step 1 — bandit (DEV-02):
    ```yaml
        - name: Run bandit security scan
          run: cd apps/api && uv run bandit -r apps/ -lll -x tests/
    ```

    Step 2 — pip-audit (DEV-03):
    ```yaml
        - name: Run pip-audit
          run: |
            # Read ignore list from .pip-audit-ignore (one CVE ID per line, # comments allowed)
            IGNORE_ARGS=""
            if [ -f ".pip-audit-ignore" ]; then
              while IFS= read -r line; do
                [[ "$line" =~ ^#.*$ || -z "$line" ]] && continue
                IGNORE_ARGS="$IGNORE_ARGS --ignore-vuln $line"
              done < ".pip-audit-ignore"
            fi
            cd apps/api && uv run pip-audit $IGNORE_ARGS
    ```

    In the `web` job, insert one new step AFTER "Install dependencies" (`pnpm install --frozen-lockfile`) and BEFORE "Build dependencies":

    Step — pnpm audit (DEV-03):
    ```yaml
        - name: Run pnpm audit
          run: pnpm audit --audit-level high
    ```

    **Part B — .pip-audit-ignore (new file at repo root):**

    Create `.pip-audit-ignore` with this exact content:
    ```
    # pip-audit ignore list
    # Format: one vulnerability ID per line (CVE-*, PYSEC-*, GHSA-*)
    # Add a comment on the NEXT line explaining why each entry is suppressed.
    # Example:
    # PYSEC-2023-1234
    # Not applicable — we do not use the affected code path (XML parsing disabled)
    #
    # IMPORTANT: Do NOT use `continue-on-error: true` in CI as a workaround.
    # Each entry here must have a documented justification.
    ```

    Note: The file must remain empty of actual CVE IDs — it is a template only.

    CI placement rationale (Claude's discretion per CONTEXT.md): bandit and pip-audit run as steps within the existing `api` job (after uv sync which makes `uv run` available). pnpm audit runs in the `web` job (after pnpm install which makes the lockfile available for audit). No separate `security` job — avoids job overhead while keeping audit steps visible in the jobs that install the deps.
