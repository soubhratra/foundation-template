    **development.py — add DDT block after BILLING_ADAPTER line:**

    ```python
    # --- django-debug-toolbar (DEV-06) — development only ---
    INSTALLED_APPS = [*INSTALLED_APPS, "debug_toolbar"]  # noqa: F405
    MIDDLEWARE = ["debug_toolbar.middleware.DebugToolbarMiddleware", *MIDDLEWARE]  # noqa: F405
    INTERNAL_IPS = ["127.0.0.1"]
    ```

    Note on MIDDLEWARE ordering: `DebugToolbarMiddleware` must be early (first in the list). The spread `*MIDDLEWARE` after it appends all existing middleware after DDT — this is correct per DDT docs. The `# noqa: F405` suppresses "may be undefined or from star imports" — same pattern used by existing development.py settings.

    No `SHOW_TOOLBAR_CALLBACK` needed — the default DDT callback already checks `INTERNAL_IPS`. The `INTERNAL_IPS = ["127.0.0.1"]` setting is sufficient for local dev without Docker network complications.

    **urls.py — add DDT URL registration at end of file, after urlpatterns:**

    After the closing `]` of `urlpatterns`, add:
    ```python
    if settings.DEBUG:
        from debug_toolbar.toolbar import debug_toolbar_urls
        urlpatterns += debug_toolbar_urls()
    ```

    The import MUST be inside the `if settings.DEBUG:` block — `debug_toolbar` is not installed in production/test environments. Moving the import outside the guard will cause `ImportError` in CI (which uses test settings) since DDT is a dev-only dep.

    DDT 6.x uses `debug_toolbar_urls()` helper function (NOT the old `include(debug_toolbar.urls)` pattern from DDT 3.x/4.x).
