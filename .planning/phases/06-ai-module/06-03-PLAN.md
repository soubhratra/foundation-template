**calculator.py:** Simple calculator tool (demonstrates numeric operations)
Use ast.literal_eval for safe expression evaluation (no arbitrary code execution):
```python
from langchain_core.tools import tool
import ast
import operator as op

@tool
def calculate(expression: str) -> str:
    """Evaluate a simple mathematical expression. Example: '2 + 2' returns '4'.
    Supports +, -, *, / operations only."""
    try:
        # Parse expression into AST
        node = ast.parse(expression, mode='eval').body

        # Define safe operators
        operators = {
            ast.Add: op.add,
            ast.Sub: op.sub,
            ast.Mult: op.mul,
            ast.Div: op.truediv,
        }

        def evaluate_node(node):
            if isinstance(node, ast.Num):  # Number
                return node.n
            elif isinstance(node, ast.BinOp):  # Binary operation
                left = evaluate_node(node.left)
                right = evaluate_node(node.right)
                return operators[type(node.op)](left, right)
            else:
                raise ValueError("Unsupported operation")

        result = evaluate_node(node)
        return str(result)
    except Exception as e:
        return f"Error: {str(e)}"
```

from langchain_core.tools import tool

@tool
def reverse_string(text: str) -> str:
    """Reverse a string. Example: 'hello' returns 'olleh'."""
    return text[::-1]

@tool
def count_words(text: str) -> str:
    """Count words in a string. Example: 'hello world' returns '2'."""
    return str(len(text.split()))

**Nodes to implement:**

1. **guardrails_node(state: QAState) -> dict:** Validate input query
   - Check query length (min 3 chars)
   - Set intent to "invalid" if validation fails
   - Otherwise set intent to "pending" and extract query from last message

2. **intent_detection_node(state: QAState) -> dict:** Route based on query type
   - Simple keyword detection (user decisions specify: "if question needs web search, use sub-agent; else use RAG")
   - If query contains keywords like "calculate", "reverse", "count" → intent = "tool_agent"
   - Otherwise → intent = "rag"
   - Real implementations would use LLM classification; this demonstrates routing without API calls

3. **rag_retrieval_node(state: QAState) -> dict:** Perform vector search
   - Import and call search_documents from apps.ai.services
   - Pass state["query"] with limit=5
   - Store results in retrieved_chunks
   - Increment loop_count for termination tracking

4. **generate_answer_node(state: QAState) -> dict:** Generate answer from chunks
   - Use ChatOpenAI(model="gpt-4o-mini", temperature=0) to generate answer
   - Construct prompt with retrieved chunks as context
   - Return answer and append AIMessage to messages
   - Increment loop_count

5. **tool_agent_node(state: QAState) -> dict:** Sub-agent with tools
   - Create agent with tools bound: [calculate, reverse_string, count_words]
   - Use create_react_agent pattern from langchain
   - Invoke with query and return answer
   - Increment loop_count

**Conditional edges:**
- `should_continue(state) -> str:` routing function
  - If intent == "invalid" → END
  - If intent == "rag" → "rag_retrieval"
  - If intent == "tool_agent" → "tool_agent"
  - If loop_count >= 10 → END (prevent infinite loops, Pitfall 3)

**Graph construction in build_qa_graph():**
```python
def build_qa_graph():
    graph = StateGraph(QAState)

    # Add nodes
    graph.add_node("guardrails", guardrails_node)
    graph.add_node("intent_detection", intent_detection_node)
    graph.add_node("rag_retrieval", rag_retrieval_node)
    graph.add_node("generate_answer", generate_answer_node)
    graph.add_node("tool_agent", tool_agent_node)

    # Add edges
    graph.set_entry_point("guardrails")
    graph.add_edge("guardrails", "intent_detection")
    graph.add_conditional_edges("intent_detection", should_continue)
    graph.add_edge("rag_retrieval", "generate_answer")
    graph.add_edge("generate_answer", END)
    graph.add_edge("tool_agent", END)

    return graph.compile()
```
