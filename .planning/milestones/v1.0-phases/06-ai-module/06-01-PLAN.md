First, add `apps.ai` to INSTALLED_APPS in `apps/api/config/settings/base.py` after `apps.core`.

Create migration 0001_initial using `python manage.py makemigrations ai` to generate Document and DocumentChunk models.

Create migration 0002_vector_extension manually with RunSQL operation:

```python
from django.db import migrations

class Migration(migrations.Migration):
    dependencies = [
        ('ai', '0001_initial'),
    ]

    operations = [
        migrations.RunSQL(
            sql='CREATE EXTENSION IF NOT EXISTS vector',
            reverse_sql='DROP EXTENSION IF EXISTS vector'
        ),
    ]
```

This uses IF NOT EXISTS to avoid permission errors in production where extension may be pre-installed by admin (Pitfall 1 from research).

Run migrations: `python manage.py migrate ai`
</action>

<task type="auto">
  <name>Task 3: Update Docker Compose for HNSW index builds</name>
  <files>
    docker-compose.yml
  </files>
  <action>
Add `shm_size: 1gb` to the `db` service in docker-compose.yml to support HNSW parallel index builds. HNSW index creation requires shared memory; Docker default (64MB) is too small and causes "could not resize shared memory segment" errors (Pitfall 2 from research).

Also add `command` override to set `maintenance_work_mem`:

```yaml
db:
  image: pgvector/pgvector:pg16
  shm_size: 1gb
  command: postgres -c maintenance_work_mem=256MB
  # ... rest of existing config
```

This ensures HNSW index builds succeed even with larger datasets during template usage.
</action>

Run `docker compose exec db psql -U foundation -d foundation -c "SHOW maintenance_work_mem;"` — should return "256MB".

</verify>
