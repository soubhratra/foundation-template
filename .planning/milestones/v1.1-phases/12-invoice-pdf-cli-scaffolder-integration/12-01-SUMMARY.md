# Phase 12 Plan 01: Invoice PDF Generation Summary

**One-liner:** WeasyPrint + Jinja2 async invoice PDF generation via Celery — POST enqueues, GET polls, never blocks HTTP.

## What Was Built

Server-side PDF invoice generation added to the billing module. A user POSTs to
`/billing/invoices/{payment_id}/pdf` and immediately receives a `task_id`. They then
poll `GET /billing/invoices/pdf-status/{task_id}` until `status=success`, at which
point the response contains a base64-encoded PDF.

The PDF is generated by WeasyPrint from a Jinja2 HTML template (`invoice.html.j2`) and
stored via the django-celery-results backend in the `task_result` TEXT column.

## Decisions Made

1. **Lazy weasyprint import** — `import weasyprint` lives inside `render_invoice_pdf()` and inside
   `generate_invoice_pdf` task body. WeasyPrint initializes fontconfig on import; importing before
   Celery forks workers causes deadlocks (WeasyPrint issue #684). This is non-negotiable.

2. **generate_invoice_pdf.delay mocked in tests** — The controller integration test patches
   `generate_invoice_pdf.delay` via `monkeypatch` to return a fake task result. This avoids
   requiring a running Redis broker in the test environment and keeps tests fast.

3. **MAX_PDF_BYTES = 512KB guard** — `render_invoice_pdf` raises `ValueError` if the rendered PDF
   exceeds 512KB. Single invoice pages are ~30-80KB; this cap prevents runaway renders from
   filling the django-celery-results TEXT column.

4. **Untyped get_pdf_status response** — The polling endpoint omits `response=` schema annotation
   because the response shape varies by task state (adds `pdf_base64` on SUCCESS, omits it otherwise).
   Django Ninja serializes plain dicts as JSON automatically.

5. **macOS conftest.py** — `apps/api/conftest.py` sets `DYLD_LIBRARY_PATH=/usr/local/lib` on macOS
   so WeasyPrint's cffi bindings can find Homebrew-installed `libgobject-2.0`, `libpango-1.0`, etc.
   This is macOS-only; Linux (Docker) finds these at standard paths automatically.

### Auto-fixed Issues

**1. [Rule 2 - Missing] macOS: WeasyPrint cannot find system libraries in test env**

- **Found during:** Task 1 GREEN phase
- **Issue:** WeasyPrint cffi bindings look for `libgobject-2.0-0` (Linux naming) but macOS Homebrew
  installs `libgobject-2.0.0.dylib`. Tests failed with `OSError: cannot load library 'libgobject-2.0-0'`.
- **Fix:** Added `conftest.py` at `apps/api/` root that sets `DYLD_LIBRARY_PATH=/usr/local/lib`
  before pytest collects tests. Pango was already installed via Homebrew; only the path was missing.
- **Files modified:** `apps/api/conftest.py` (created)

**2. [Rule 2 - Missing] Integration test needs broker mock**

- **Found during:** Task 2 GREEN phase
- **Issue:** `test_request_invoice_pdf_returns_task_id` called `generate_invoice_pdf.delay()` which
