## Integration Findings

### HIGH Priority (Blockers)

#### BREAK-1: Stale test URL — test_context_has_duration_ms fails (OBS-01)

- **File:** `apps/api/tests/core/test_middleware.py` lines 21, 27, 38, 44–45
- **Root cause:** Phase 13-02 subagent used `/api/v1/health` as the test endpoint (valid at the time). Phase 15-02 removed the old `HealthController` and moved health probes to `/api/health/live|ready|startup`. `test_middleware.py` was not updated.
- **Impact:** `test_context_has_duration_ms` asserts `status_code in (200, 503)` but receives 404. Three other middleware tests still pass (they only assert on the `X-Request-ID` header, which middleware correctly injects on 404 responses).
- **Fix:** Change all 5 occurrences of `/api/v1/health` in `test_middleware.py` to `/api/health/live`.

#### BREAK-2: Redis env vars not injected into Docker Compose (SEC-01, SEC-03, OBS-05)

- **Files:** `docker-compose.yml`, `docker-compose.prod.yml`
- **Root cause:** Phase 16 configured `CACHES["default"].LOCATION = CACHE_REDIS_URL` (default `redis://localhost:6379/1`) and `CACHES["sessions"].LOCATION = SESSION_REDIS_URL` (default `redis://redis:6379/2`). Neither variable is in any Compose service `environment:` block. Inside containers, `localhost` is the container itself — not the `redis` service.
- **Impact:** At runtime in Docker Compose:
  - Rate limiting counters (SEC-01) connect to localhost:6379 → timeout → `RATELIMIT_FAIL_OPEN=True` passes requests through (fails open rather than erroring)
  - Django sessions (SEC-03) attempt localhost:6379 → timeout on first session write
  - `celery-beat` task scheduling (OBS-05) inherits the same broken cache backend
- **Fix:** Add to `docker-compose.yml` and `docker-compose.prod.yml` for services `api`, `celery-worker`, `celery-beat`:
  ```yaml
  CACHE_REDIS_URL: redis://redis:6379/1
  SESSION_REDIS_URL: redis://redis:6379/2
  ```

### MEDIUM Priority

#### BREAK-3: Schemathesis CI job missing Redis service (DEV-05)

- **File:** `.github/workflows/ci.yml` `schemathesis` job
- **Root cause:** The `api` test job overrides `CACHES` to `LocMemCache` via autouse fixture, avoiding Redis. The `schemathesis` job starts a live `runserver` with `DJANGO_SETTINGS_MODULE=config.settings.development` — no Redis service declared.
- **Impact:** Cache and session middleware degrade silently. Rate limit counters fail open (`RATELIMIT_FAIL_OPEN=True`). Most schemathesis runs succeed (auth paths excluded), but the test environment doesn't match production.
- **Fix:** Add `services: { redis: { image: redis:7-alpine, ports: ["6379:6379"] } }` to the `schemathesis` CI job.
