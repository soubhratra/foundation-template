## Unsatisfied / Partial Requirements

### HIGH: AKEY-01, AKEY-02, AKEY-03 — ApiKeyAuth never wired to any endpoint

**Phase 28** implemented `ApiKeyAuth` (HttpBearer Ninja auth backend), `RequireScope` (permission class), and `ApiKeyRateLimitMiddleware` — all verified by 30 passing tests. However, **no production Ninja controller registers `auth=[..., ApiKeyAuth()]`**. The API key authentication flow — Bearer token lookup, rate limiting, scope enforcement, last_used_at tracking — is fully built but disconnected.

Products using this template must wire `auth=[..., ApiKeyAuth()]` and `permissions=[RequireScope("scope")]` themselves. As a template, this may be intentional (products define their own scoped endpoints). However, there is no example or stub endpoint demonstrating the pattern, and the requirements text says the system "enforces scope per endpoint" and "tracks last_used_at... updated on every authenticated request" — neither can be true if no endpoint uses the auth class.

**Affects:** AKEY-01, AKEY-02, AKEY-03

---

### HIGH: HOOK-01 — fire_webhook_event() has no production callers

**Phase 27** implemented `fire_webhook_event()` in `apps/webhooks/utils.py` and defined `WEBHOOK_EVENTS` in settings with three events (`user.created`, `subscription.updated`, `org.member_added`). However, **none of these events are dispatched from any service, signal, or task in production code**.

The full delivery pipeline (Celery + HMAC + retry + circuit breaker) is implemented. But it is permanently idle — no user action causes a webhook to fire.

**Affects:** HOOK-01

---

### MEDIUM: ORG-02 — InvitationService.invite() sends broken URL

**apps/api/apps/orgs/services.py line ~217:** `accept_url` is hardcoded to `'https://app.example.com/accept-invite?token={token}'`. The `FRONTEND_URL` setting exists in `base.py:312` but is not read here. Every invitation email in any deployed environment contains a non-functional link.

**Fix:** `f"{settings.FRONTEND_URL}/accept-invite?token={invitation.token}"`

**Affects:** ORG-02

---

### MEDIUM: AUDIT-01 — APIKey events unreachable in org audit log

`get_audit_log_page()` in `apps/audit/selectors.py` filters pghistory events by `org_id`. The `/me/api-keys` controller does not apply `IsOrgMember`, so `request.org` is never set, so `AuditContextMiddleware` never injects `org_id`. APIKey creation and revocation events are recorded by pghistory but are filtered out of the org audit log query — invisible to org admins.

This is a design tension: API keys are user-owned (not org-owned), so no `org_id` in context is correct behavior. But AUDIT-01 requires "Changes to APIKey recorded via pghistory triggers; AuditContextMiddleware attaches user and org context automatically."

**Affects:** AUDIT-01

---

### LOW: BILL-01 / ADMIN-01 — OrgCustomer not registered in admin

`OrgCustomer` has no `ModelAdmin` registration. Staff cannot inspect or modify per-org billing records from the django-unfold interface. UNFOLD sidebar has no OrgCustomer link.

**Affects:** BILL-01, ADMIN-01

---

### TECH DEBT: BILL-02 — \_resolve_org_plan_id() always returns None

`_resolve_org_plan_id()` in `orgs/services.py` returns `None` until a per-org `Subscription` model is implemented. `has_org_feature()` therefore always falls back to the user's personal plan. The org-plan-takes-precedence behavior is not functional. This is documented in code comments.

**Affects:** BILL-02
