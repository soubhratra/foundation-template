## Milestone Summary

**Inserted Phases:**

- Phase 24: Social Auth OAuth Callback Pages (inserted after Phase 23 to close INT-01, INT-02 from milestone audit)
- Phase 25: GDPR Export plan_id Accuracy (inserted after Phase 23 to close INT-03 from milestone audit)

**Key Decisions:**

- ESP decision: Resend (not SendGrid) — anymail dropped official SendGrid support June 2025; `RESEND_API_KEY` in `.env.example`
- Apple Sign In: dedicated server-side native token verification endpoint required — Expo JWT audience (`aud` = Bundle ID) differs from Allauth standard endpoint expectation
- Social email merge: `SOCIALACCOUNT_EMAIL_AUTHENTICATION_AUTO_CONNECT=True` for Google + GitHub; disabled for Apple relay addresses
- GDPR deletion: `UserDeletionService` orchestrator required — `user.delete()` alone leaves orphaned Stripe + PostHog data (Article 17)
- Entitlement cache key: `entitlements:{user.pk}` with 300s TTL; invalidated unconditionally on `customer.subscription.updated`
- `RequireRole` returns `False` (not `raise PermissionDenied`) — ninja_extra converts `False` to `HttpError 403`

**Issues Resolved:**

- INT-01: Missing OAuth callback page at `/auth/callback` (Phase 24)
- INT-02: Missing OAuth error page at `/auth/error` (Phase 24)
- INT-03: GDPR export always returning `plan_id: null` (Phase 25)

**Issues Deferred:**

- No "Download my data" button in `/settings` UI (GDPR-02 non-critical gap)
- `AdminController` not using ninja auth stack (uses Django middleware instead — functional but departs from pattern)

**Technical Debt Incurred:**

- `UserDeletionService.execute()` in `services.py` and `delete_user_account` Celery task in `tasks.py` both implement the same 4-step GDPR cascade — future changes must be applied in two places
