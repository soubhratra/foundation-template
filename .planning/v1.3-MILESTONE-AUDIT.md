## Integration Checker Report

### Critical Integration Gaps

#### INT-01 + INT-02: Missing OAuth Callback and Error Pages (SOCIAL-01, SOCIAL-02)

**Severity: Critical — Social login is functionally broken for web users**

`SocialButtons` POSTs to `/api/v1/auth/browser/v1/auth/provider/redirect` with `callback_url: "/auth/callback"`. After Google/GitHub OAuth completes, allauth redirects the browser to `/auth/callback` (Next.js). No such page exists in the route tree:

- No `apps/web/app/(auth)/callback/page.tsx`
- No `apps/web/app/(auth)/error/page.tsx` (configured in `HEADLESS_FRONTEND_URLS.socialaccount_login_error`)

**Impact:** Google and GitHub social login fail with a 404 after the OAuth provider redirects back. Apple Sign In (mobile, SOCIAL-03) is **not affected** — it POSTs directly to `POST /api/v1/auth/apple/` without a browser redirect.

**Fix:** Create `apps/web/app/(auth)/callback/page.tsx` that reads the allauth session cookie and calls `useAuth().refetch()` before redirecting to the dashboard. Create `apps/web/app/(auth)/error/page.tsx` to handle OAuth errors gracefully.

#### INT-03: AccountExportService Returns Stale plan_id (GDPR-02)

**Severity: Non-critical — Export works but returns incomplete data**

`AccountExportService.export()` in `apps/api/apps/accounts/services.py` contains `plan_id = None` with comment: _"plan_id is not stored on Subscription directly"_. Phase 23 added `Subscription.plan_id` as a CharField, populated by the `customer.subscription.updated` webhook handler. The export service predates this and was not updated.

**Impact:** `GET /api/v1/account/export` returns `"subscription": {"plan_id": null}` even for users with a resolved plan. No data is exposed incorrectly — it just returns null instead of the actual plan identifier.

**Fix:** Update `AccountExportService.export()` to read `subscription.plan_id` from the ORM instead of hard-coding None.
